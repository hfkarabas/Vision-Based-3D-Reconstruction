# UAV reconstruction release evaluation

**Acceptance verdict: PASS WITH LIMITATIONS.** The Windows desktop and CLI workflows produced real photographic GLB and OBJ assets from overlapping UAV photographs. The release supports partial, open-surface reconstruction for an engineering demonstration. It has no survey-grade accuracy claim.

## Workflow and validation

The pipeline decodes and fingerprints each source photograph, estimates or loads intrinsics, and registers cameras with incremental SfM and bounded bundle adjustment. OpenCV rectifies registered stereo pairs and estimates reciprocal disparity. Independent depth observations corroborate samples before world-voxel fusion. Image-grid triangles form the open surface, which is cleaned and simplified under sampled deviation bounds. Visible registered photos provide UV atlas regions. Open3D loads the PLY and GLB in a separate process. Blender is an independent validation tool.

| Gate | Evidence |
|---|---|
| Real photos to model | The no-cache Rural-40 CLI run ingested 40 DJI originals and registered 28. It produced 6,715 sparse landmarks, 896,742 dense points and 437,682 optimized faces. Blender imported all 437,674 faces in the final GLB and OBJ after export-precision cleanup. |
| Camera and depth support | The registered graph is connected. Sparse residuals are 0.598 px median and 0.865 px RMS. The workflow checker verified finite colored dense points and accepted depth support. |
| Surface integrity | The optimized fresh mesh passed edge, winding, degeneracy and normal checks. Bounded intersection probes still detect crossings in selected assets. |
| Photo export | Blender passed GLB and OBJ imports for the fresh run and all three selected bundles. Checks cover triangle counts, finite geometry, normals, material and atlas binding, and UVs. Twelve release replay renders were pixel-identical. |
| Desktop | The actual Tk worker processed 12 photos, registered four, produced 177,580 dense points and exported both photo formats in 53.15 s. The Tk event loop advanced 484 checks. A second run was cancelled after its reconstruction log opened. |
| Interactive viewer | Open UV GLB opened the saved Urban model from the visible desktop app. Mouse orbit, keyboard pan, wheel zoom and F fit/reset were verified visually. Closing the viewer restored the controls. A Rural model that initially cropped at the bottom fit after the camera fix. Ctrl-drag pan and manual source-photo selection were outside the interactive check. |
| Reproducibility | A 36.39 s resume from the fresh run's dense mesh regenerated byte-identical GLB, OBJ, MTL and atlas. The full suite passed **216 tests**, with 14 dependency deprecation warnings. The final targeted suite passed **62 tests**. The installed uv environment passed its 75-package compatibility check. |

The fresh run took 376.48 s. Its manifest records 307.37 s sparse, 31.53 s dense, 21.51 s surface and 16.06 s texture. The process peak working set was about 1.81 GiB. These are measurements on the development workstation. A previously timed cache-assisted run took 143.06 s and is a different configuration.

## Selected models and measured limitations

| Scene | Cameras | Dense points | GLB/OBJ faces | Photo area | GLB edge components |
|---|---:|---:|---:|---:|---:|
| Rural-40 | 28/40 | 962,839 | 628,000 | 36.17% | 2,641 |
| Urban-40 | 35/40 | 1,746,603 | 1,066,467 | 22.77% | 3,525 |
| Rural-80 | 47/80 | 292,071 | 584,964 | 37.91% | 430 |

Rural-40 retains the earlier conditioned plus alternate-witness geometry. Its fixed strip probe remains clear in the saved benchmark, with offset-aligned DSM P95 of 11.904 m versus 32.028 m in the unconditioned comparison. Urban retains the conditioned model because the alternate-witness variant increased components from 3,525 to 3,681. Its offset-aligned DSM P95 is 8.306 m. Rural-80 registered 47 cameras across four approximate PPK clusters. Its own conditioned versus recovery DSM P95 was 6.724 versus 6.664 m in a different alignment. These comparisons measure elevation residuals against the supplied DSM after approximate alignment. The vertical datum and absolute scale are unverified.

Rural-80 uses the same underlying surface with a bounded visibility subdivision. Photographic area rose from 32.83% to 37.91% at the same 2048 atlas resolution. The export grew from 397,979 to 584,964 faces. Both formats passed Blender checks, and both matched-frame silhouettes had IoU 1.000 in top and oblique views. Areas without a suitable photograph use the GLB vertex-color fallback or the OBJ neutral material.

The ball-pivoting alternative eliminated detected crossings in the 16 frozen patches while retaining only 28–68% of grid triangle area and increasing fragmentation in every patch. It was rejected. The source-grid evidence attributes over 99% of sampled raw intersections to different image grids. It does not distinguish every physical cause of the remaining layers. Selected release meshes have open boundaries and nonadjacent overlaps in bounded probes. These probes are neither whole-mesh counts nor a certificate of manifoldness.

The opt-in empty-primary-depth trial recovered 307 samples and 281 fused points in Rural-48, adding 27 half-meter cells with effectively unchanged DSM P95 (13.33853 to 13.33807 m). The other three scenes recovered zero empty pixels. It remains dense-only. The Urban PnP ablation kept 35/40 cameras, 6,066 landmarks and the same 0.731/0.948 px median/RMS reprojection error. Release registration counts and default profiles were retained. Unity import and other hardware are unverified.

## Reproduce

Run from the repository root. The command log lists the exact Rural-40 source files and the position-hint artifact. Replace the output argument with a new directory before replaying.

```powershell
$p = 'outputs/airzoo-benchmark/mission-iii-d'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '2'
$replay = @(Get-Content "$p/production-fresh-command.json" -Raw | ConvertFrom-Json)
$replay[[array]::IndexOf($replay, '--output') + 1] = "$p/production-fresh-replay"
.venv/Scripts/python.exe -B -m vision3d.cli @replay
.venv/Scripts/python.exe -B scripts/verify_uav_workflow.py --run "$p/production-fresh-replay" --output "$p/replay-gates.json"
```

For release packaging, point `$blender` at the local Blender executable. Each scene argument identifies a selected texture-stage directory and its source revision. The builder resolves the earlier stage paths from the saved metadata, hashes the exported bytes and binds the reports to the copied files.

```powershell
$a = 'outputs/airzoo-benchmark'
.venv/Scripts/python.exe -B scripts/build_uav_release.py --output outputs/final-release/rebuild `
  --blender $blender `
  --scene rural "$a/mission-iii-c/rural-texture" 661fe54 `
  --scene urban "$a/geometric-root-cause-recovery/urban-final-texture" a69be3e `
  --scene rural80 "$a/mission-iii-d/rural80-texture-refined" dc4f83a `
  --reference outputs/final-release/release-candidate/validation
```

The desktop validation can be repeated with `scripts/validate_uav_desktop.py --images <12 overlapping images> --output <new directory>`. The recorded exact input list is in the desktop report.
