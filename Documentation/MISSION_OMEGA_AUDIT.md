Research title: **Hesaplama Kaynakları Kısıtlı Büyük Ölçekli İHA Görüntülerinde Kalite Geri Beslemeli Bölgesel Adaptif 3B Rekonstrüksiyon**

Original work remains untouched. Git initially contained modified/deleted deliverables and untracked research. `.git` is read-only in this session; no staging, commit, reset, clean, lock removal or historical output deletion is attempted. The initial status is preserved in `outputs/mission-omega/00_inventory.json`. All new computation is under `outputs/mission-omega/`.

The two 12 November source documents were found under `Documentation/MISSION_OMEGA_SOURCE_RESEARCH/`, not directly under Documentation. The technical decision and screening register were read alongside the foundation, audit, hypothesis, architecture, prior-work review, Mission 0 results, original run script and baseline adapters. The 147-item register is title/bibliographic screening, not 147 full-text reviews.

Actual originals: Rural `datasets/airzoo/rural/Scene2/query` has 190 JPG; Urban `datasets/airzoo/urban/Scene1/query` has 161 JPG. Both are 4032×3024. New SHA-256 verification is in the inventory. Query folders also contain five ancillary positioning files each. XMP includes RTK positions, gimbal orientation and altitude metadata. Supplied reference DOM/DSM are excluded from production geometry and scheduler inputs. Their known CRS-header/sidecar inconsistencies and unresolved vertical datum preclude treating them as independent ground truth.

Reused: independent cached COLMAP camera solutions and genuine 900-pixel image-derived fused clouds, source-image hashes/metadata, and the historical camera-to-RTK similarity transform. Camera fit is in-sample registration, not independent survey accuracy. Neither old Poisson/Delaunay nor rejected native surfaces are used as final terrain geometry. Sparse SfM is not rerun.

ODM's official Linux/Docker route was checked first. Docker is absent; `wsl --status` and `wsl --list --verbose` report that WSL is not installed. No security settings or Windows optional components were changed. The supported fallback is COLMAP dense reconstruction → PDAL ELM/SMRF/MAD → rasterio/GDAL rasters → QGIS/Qgis2threejs DEM surface → official Three.js GLTFExporter → native Blender import/export/render. This is **not an ODM run**.

PDAL/GDAL and QGIS were installed through conda-forge into workspace-local prefixes. An attempted Qt5 WebEngine package caused a QGIS downgrade and DLL incompatibility in the first disposable QGIS prefix; that prefix is not used. The clean `tools/qgis4` prefix pins QGIS 4.2.3 and `pyqt6-webengine`. Native scene export bindings and embedded QtWebEngine remained incompatible. The maintained Qgis2threejs exporter successfully writes its scene without WebEngine; an isolated installed Chrome session loads that scene and invokes the unmodified Three.js glTF exporter. No terrain triangulation/UV/renderer algorithm was written.

The source snapshot of Qgis2threejs is commit `922f1663e4767361fc98205d005ac63c8cfaa447`, recorded in the GitHub archive comment. Standard npm/esbuild builds its published TypeScript. The export adapter contains a narrowly scoped binding workaround for the unsuccessful embedded exporter; the successful `--web` path does not need that workaround.

First Rural strict raster attempts exposed negative outliers; they are retained under `raw/rural/` and `v2-elm/`. The third attempt adds PDAL's existing MAD filter. A separate production variant masks local quality residuals above 3 m and invokes GDAL FillNodata with an explicitly bounded 8 m radius. Original science rasters and interpolation masks remain separate. Terrain beneath vegetation/buildings is inferred, not observed bare earth.

The first texture is a point-color projection and is named accordingly. A subsequent real photograph texture is generated by COLMAP mesh_texturer on the DTM-derived surface. An orthographic emission render is a **photo-textured DTM projection**, not an ODM orthophoto or building-correct true orthophoto. The orthographic raster's exact bounds and resolution are recorded. A float32 composition precision issue was detected and corrected by composing local/projected/SfM transforms in NumPy float64 before passing the small local transform to Blender.

Urban ground inference has substantially lower support and larger elevation/edge outliers; the full-area diagnostic is not accepted as a complete urban asset. No footprint is fabricated. An OSM/Overpass query was rejected by automatic approval review because GPS-derived bounds would leave the computer; separate explicit consent was requested. No such request was transmitted. No local open building vector was found in the inspected source/cache folders.

The machine reports RTX 5070, 12,227 MiB VRAM, driver 617.42, 16,782,508,032 bytes RAM and 14 logical CPUs. Initial available RAM was approximately 4.55 GB and free disk 314.7 GB. CIM queries are denied, so psutil supplies current resource measurements. Stages use two CPU threads and bounded caches. Unity 6000.6.1f1 is installed and a real glTFast smoke test is pending; availability alone is not import verification.
